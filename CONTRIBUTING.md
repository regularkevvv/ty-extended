# Contributing

The Rust companion is developed in `companion/`. Official ty is developed by
[Astral](https://github.com/astral-sh/ruff/tree/main/crates/ty); the companion talks
to a separately installed checker through its public command line and LSP.

```shell
git clone --recurse-submodules https://github.com/regularkevvv/ty-extended.git
cd ty-extended
cargo +1.98.0 build --locked --manifest-path companion/Cargo.toml
```

The pinned `ruff` submodule supplies parser, notebook, plugin-host and protocol
crates. Changing companion behavior generally does not require changing it.
Changes to those shared crates belong in `ruff-extended`, followed by an explicit
submodule update. Do not merge each upstream ty release into this repository.

## Validation

Install reference checkers in separate environments. See
[the acceptance guide](companion/tests/DJANGO_ACCEPTANCE.md) and
[the compatibility runner](companion/scripts/checker_compatibility.py).
Unit tests requiring a live checker fail when `TY_COMPANION_TEST_OFFICIAL` is missing.
Set `TY_COMPANION_TEST_FORK` for differential integration tests.

```shell
cargo +1.98.0 fmt --manifest-path companion/Cargo.toml --check
cargo +1.98.0 clippy --locked --manifest-path companion/Cargo.toml --all-targets -- -D warnings
TY_COMPANION_TEST_OFFICIAL=/path/to/official/ty \
  cargo +1.98.0 test --locked --manifest-path companion/Cargo.toml
python3 -m unittest discover -s companion/tests -p 'test_*.py'
```

Keep real checker, installed-package, editor and hosted CI results separate.
Do not change existing positive or negative expectations to hide an upgrade failure.
Record executable hashes and tested versions with compatibility evidence.
Use `CARGO_BUILD_JOBS=2` and `CARGO_INCREMENTAL=0` on shared machines, preserve
required test binaries outside the build tree, and run `cargo clean` after each
build/test phase.

## Packaging and releases

The Python distribution uses Maturin to package the companion executable and
`ty_extended` SDK module. It depends on official ty and must not install its files
or the `ty` command. See [publishing](docs/release-publishing.md).

Parts of `.github/workflows/release.yml` are generated by cargo-dist. Change
`dist-workspace.toml` or reusable workflows, regenerate with the pinned cargo-dist
version, and inspect the generated diff. Follow [AGENTS.md](AGENTS.md) when reviewing
or changing release automation.
